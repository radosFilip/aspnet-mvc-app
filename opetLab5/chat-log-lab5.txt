3. KORISNIK

Pojasni mi malo više API i DTO

ASISTENT
DTO znaci Data Transfer Object. To je klasa koja opisuje sto API prima ili vraca, odvojeno od stvarnih EF modela iz baze.

Primjer: Post model u bazi ima navigacije Author, Comments, Likes, Reports, Tags. Ako API vrati cijeli Post direktno, JSON moze povuci previse podataka ili napraviti kruzne reference. Zato postoji PostDto koji vraca samo ono sto klijentu treba: id, title, content, category, createdAt, author summary, tags, commentCount i likeCount.

Za unos postoje posebni DTO-i, npr. PostCreateUpdateDto. Klijent ne salje cijelog autora ili tag objekte, nego samo AuthorId i TagIds. API onda provjeri postoje li ti zapisi i poveze ih.

API controller ne vraca HTML view, nego JSON. Primjer ruta:
- GET /api/posts
- GET /api/posts/1
- POST /api/posts
- PUT /api/posts/1
- DELETE /api/posts/1

[ApiController] pomaze kod API ponasanja i validacije, a ControllerBase se koristi jer API controller ne treba viewove.

Mapiranje je u ApiDtoMapper.cs. Primjer: post.ToDto() pretvara EF entitet Post u PostDto. Zato controller moze vracati Ok(post.ToDto()).

API vraca HTTP status kodove: 200, 201, 204, 400, 404, 409. Ukratko: API je ulaz/izlaz aplikacije za druge klijente, a DTO je kontrolirani oblik podataka koji kroz taj API smije proci.

U ovom projektu sada postoje dva paralelna sloja:

Postojece MVC stranice i dalje rade isto: /Posts, /Posts/Details/1, /Users, /Tags.

Novi API radi preko ruta:
- /api/posts
- /api/users
- /api/tags
- /api/comments
- /api/likes
- /api/follows
- /api/messages
- /api/notifications
- /api/reports

Za GET /api/posts controller uzme podatke iz baze preko AppDbContext, ucita povezane podatke preko Include, pretvori Post entitet u PostDto i vrati JSON s Ok(...).

Za GET /api/posts/1 API trazi post po ID-u. Ako postoji vraca 200 OK i JSON, ako ne postoji vraca 404 Not Found.

Za POST /api/posts klijent salje JSON s title, content, category, authorId i tagIds. API validira autora i tagove, kreira Post entitet i sprema ga u bazu. Ako uspije vraca 201 Created.

Za PUT /api/posts/1 API trazi post, validira podatke, mijenja dopustena polja i vraca novi DTO.

Za DELETE /api/posts/1 brise zapis i vraca 204 No Content, a za nepostojeci ID 404.

MVC controlleri vracaju View(...), API controlleri vracaju Ok(...), CreatedAtAction(...), NotFound(...) i slicno. Oba sloja rade nad istom bazom i istim entitetima.

Tok:
HTTP zahtjev -> /api/posts -> PostsApiController -> AppDbContext -> SQL Server baza -> Post entitet -> ApiDtoMapper.ToDto() -> PostDto -> JSON odgovor.

18. KORISNIK
================================================================================
Da Google login stvarno radi, u Google Cloud Console trebaš postaviti redirect URI:
https://localhost:7218/signin-google
Zatim unesi vrijednosti ovdje:
"Authentication": {
  "Google": {
    "ClientId": "OVDJE_CLIENT_ID",
    "ClientSecret": "OVDJE_CLIENT_SECRET"
  }
}

Jel ovo ja trebam sam postaviti ili već si to napravio?

ASISTENT
To moras sam postaviti u Google Cloud Console, jer ClientId i ClientSecret pripadaju tvojem Google OAuth projektu i ja ih ne mogu znati niti generirati lokalno bez tvog Google racuna.

Ja sam napravio kod koji podrzava Google login. U appsettings.json su mjesta za ClientId i ClientSecret. Kad u Google Cloud Console kreiras OAuth Client, dodas:
https://localhost:7218/signin-google

Onda kopiras ClientId i ClientSecret u appsettings.json. Nakon toga Google prijava moze raditi.

This content isn't available right now
Invalid Scopes: email. This message is only shown to developers. Users of your app will ignore these permissions if present. Please read the documentation for valid permissions at: https://developers.facebook.com/docs/facebook-login/permissions

ASISTENT
Popravio sam Facebook login za gresku Invalid Scopes: email.

Problem: ASP.NET Facebook login po defaultu moze slati email scope, a tvoja Meta aplikacija ga trenutno ne prihvaca. Zato Facebook prekine prijavu prije povratka u aplikaciju.

Promjene:
- U Program.cs dodan je options.Scope.Clear() za Facebook.
- Facebook login vise ne trazi email permission.
- U AuthController.cs login moze kreirati korisnika i ako Facebook ne vrati email adresu.

Ako Facebook ne vrati email, korisnik se povezuje preko Facebook provider ID-ja, a aplikacija generira korisnicko ime iz Facebook_{id}. Build prolazi.

prilikom prijave ispise mi Email " is invalid. i ne prijavim se kao novi korisnik

ASISTENT
Popravio sam gresku Email "" is invalid kod Facebook prijave.

Problem: Facebook ti ne vraca email adresu, a ASP.NET Identity ne zeli kreirati korisnika s praznim/neispravnim emailom.

Promjena u AuthController.cs:
- Ako Facebook ne vrati email, aplikacija generira internu valjanu adresu oblika facebook_{facebookId}@external.local.
- EmailConfirmed je false za takav fallback email.
- Korisnik se povezuje preko Facebook provider ID-ja, tako da se sljedeci put prijavljuje na isti lokalni racun.
- Ako Google/Facebook vrati pravi email, i dalje se koristi pravi email.

26. KORISNIK
================================================================================
kako se admin razlikuje od korisnika

ASISTENT
Admin i obicni korisnik razlikuju se po roli u ASP.NET Core Identity sustavu.

Postoje role:
- Admin
- User

Admin racun:
admin / Admin123!

Admin moze:
- pristupiti starim CRUD kontrolerima za entitete kao sto su komentari, lajkovi, poruke, obavijesti, prijave i pracenja
- uredjivati i brisati tudje postove
- uredjivati i brisati korisnike
- uredjivati tudje profile/profilne slike
- upravljati tagovima/kategorijama gdje je to ograniceno admin pravilima

Obicni korisnik moze:
- pregledavati javni dio aplikacije
- pregledavati druge korisnike, postove i kategorije
- kreirati novu objavu ako je prijavljen
- uredjivati i brisati samo svoje postove
- uredjivati svoj profil i svoju profilnu sliku
- ne moze pristupiti admin CRUD popisima svih entiteta

Anonimni korisnik moze pregledavati javni sadrzaj, ali ne moze kreirati, uredjivati ni brisati.
